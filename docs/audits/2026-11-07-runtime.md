# Runtime and resource audit, 2026-11-07

## Scope and limits

The repository-wide inventory covered 607 code files (about 85,455 lines, including
the vendored QR decoder). Syntax checks covered 599 shell files/profiles, 29
JavaScript files, eight Python files and four JSON files. Translation validation
covered 2,027 messages without duplicates. The optional C helper built with
`-Wall -Wextra -Wpedantic -fanalyzer` without diagnostics on the development host.

Focused manual review followed the paths between collectors, per-modem caches,
sessionwatch, statistics, telemetry, modem discovery, protocol setup, AT locking,
SMS/USSD/eSIM operations, background refreshes and browser polling. ShellCheck
was also run over 571 root scripts/profiles. Its findings were triaged: shared
profile variables and BusyBox extensions are not failures simply because a
POSIX/dash-oriented check reports them.

This is a static and fixture-based audit, not a claim that every hardware/firmware
combination was exercised. Installation, modem resets, live SIM switching and
paid SMS were not used as validation. The 21 changed runtime files were subsequently deployed to `192.168.11.1`
at the user's request. The previous files and configuration were backed up at
`/root/5gmodem-backups/runtime-audit-20261107-091045/before.tar.gz`.
All deployed checksums and shell syntax checks passed; all six web assets matched
over HTTP. The modem interface remained up and sessionwatch remained running.
Configuration checksums were unchanged. Network services were not restarted. Existing local Huawei, band-parser and mobile-layout changes
were preserved. Automatic protocol registration and the default LuCI footer
were not changed.

## Implemented changes

| Area | Trigger and previous behaviour | Result |
| --- | --- | --- |
| Telemetry identity | Switch between modems with equal uptime stamps; the shared cache could reuse the previous modem's fields | Cache key includes snapshot path and stamp |
| Telemetry freshness | A future stamp passed the upper-bound-only age check; a stale carrier IP could still be published | Nonnegative age required; carrier IP requires a fresh snapshot |
| Telemetry conversion | Every integer/string conversion launched awk/sed | Integers and plain strings use shell builtins; fractional rounding and escaping remain supported |
| Telemetry JSON | A control character could split the three-line snapshot cache | Control characters are removed during string escaping |
| Statistics | Page and daemon ticks could read and replace the same traffic baseline concurrently | One collector holds a nonblocking flock; a competing tick skips its round |
| Statistics labels | A lazy snapshot loaded inside a command substitution was lost on return | One `netpri.sh list` snapshot is loaded in the parent collector |
| Persistent storage | A directory probe created/deleted `.wtest`; an unmounted custom path was created before the mount check | Mount is checked first; existing directories use builtin writability checks without probe writes |
| Detached operator refresh | A background child inherited caller lock descriptors and `_AT_LOCK_HELD` | The child closes descriptors 7/8/9 and clears the inherited ownership flag |
| Interface hotplug | Manual-network reapply missed quoted UCI values; two background workers retained caller descriptors | Match normal UCI quoting and release inherited descriptors before background work |
| Hidden browser tabs | Metrics, inbox, statistics, uplink/widget and external-IP timers kept making RPC calls | Automatic polls skip hidden tabs and resume at the normal interval when visible |
| eSIM, USSD, direct SIM-slot fallback | Some AT paths continued after lock acquisition failed | They report busy or serve a read cache before touching the port |
| SMS PDU sending | A low-level entry point relied on its caller's port lock | The PDU sender explicitly acquires the requested port lock |
| Huawei session identity | Two devices exposed the same private address and shared session/backoff files | Cache and lock identity include modem path and address |
| Huawei POST serialization | A killed process could leave a directory lock permanently busy | A scoped nonblocking flock releases automatically when its owners exit |
| Legacy HiLink fallback | ZTE model assignment executed the model as a command; MCC assignment/output variables were wrong; Huawei NOSERVICE test lacked a closing-bracket space | Corrected assignments, quoted temporary paths and the shell test |

The SMS read timeout exception is deliberately preserved. `sms.md` explicitly
requires a normal read to proceed after its ordinary lock wait times out. It
still yields to a marked long AT operation. A blanket `_sms_run` lock-failure
guard was considered and removed after checking this contract; regression tests
now protect both behaviours. Sending has a stricter policy than reading.

## Validation

- All modem/band profile smoke runs: **3,176 runs, zero failures**. These use
  isolated fake tools and recorded/synthetic replies, not live devices.
- `tools/issue-regressions/test_runtime_audit.py`: telemetry cache isolation and
  freshness, number/string handling, collector exclusion, mount-check ordering,
  shared label snapshot, detached descriptor cleanup, busy-port paths, legacy
  HiLink handling and the intentional SMS-read exception.
- `tools/issue-regressions/test_background_polling.cjs`: executes the affected
  JavaScript polling callbacks with hidden/visible document states and checks
  that RPC calls resume.
- `tools/hilink-tests/test_huawei.py`: SMS XML layouts/errors, login/session
  handling, independent sessions for equal private addresses, and POST lock recovery after killing its owner.
- `tools/issue-regressions/test_band_pref.py`: existing wrapped band-list
  regression.
- Syntax checks repeated for the changed runtime files; `git diff --check` passed.

An isolated BusyBox-ash benchmark on the development PC converted 400 integers
and 200 ordinary strings per sample. Median of three samples: 0.3319 s before,
0.0044 s after. The corresponding awk/sed invocations fell from 600 to zero.
This measures only these helper functions; it does **not** establish a router-wide
CPU reduction or a comparable speed-up of an entire poll.

## Further work requiring targeted evidence

- HiLink metric collection has its own cache path before the general poll lock.
  Multiple consumers, including direct `hilink.sh json` calls in netpri, can
  still duplicate HTTP work. Unifying those consumers requires concurrency
  tests for initial loads, failed refreshes and session/token rotation.
- Telemetry and other shell consumers still launch many jsonfilter processes.
  Batch extraction is a candidate, but must retain shell-safe quoting, absent
  fields, zeroes and multiline data. The helper changes above do not alter this
  parser contract.
- Some watchdogs bound only their immediate child. Long-lived descendants and
  inherited descriptors need process-tree tests before replacing timeout logic.
- The optional MTK C bridge warrants backpressure tests: its nonblocking write
  helper treats EAGAIN as completion, and some callers ignore write failures.
  The compiler analysis alone does not validate this behaviour.
- Reports about installation/network interruption, missing incoming SMS and
  firmware-specific USB compositions still require their own evidence. Reducing
  poll frequency or changing automatic setup is not a demonstrated fix for them.

The 4PDA refresh and modem-specific evidence are recorded separately in the
local knowledge-base audit directory. Forum reports describe observations;
hardware capability claims and suggested firmware commands are not automatically
turned into application changes.


## 4PDA knowledge-base refresh

The refresh checked 249 previously populated topic archives. Of those, 218 accepted an update; 31 retained the old canonical copy after a shorter response or parsed result. The accepted updates added 3,157 records by count difference. Eight additional source topics contributed 4,697 records, for 7,854 added records altogether. These are newly archived sources, not a claim that eight new modem models were released. One SW08 topic link returned HTTP 404. Five older empty placeholders remain empty; a separate retry stopped when the browser could not load the forum.

Old raw/JSONL copies and rejected fresh pages were retained separately. Modem summaries were updated with source topic, local record number and date. The refresh distinguishes observed replies from forum guesses: SMTP power-table entries do not establish selectable bands; Compal 3CA/NSA observations do not establish a parser defect; reports about QManager SMS do not establish the same cause in this application. No modem support profile or automatic firmware command was added from marketing descriptions alone.

The final focused checks passed: 18 runtime regression tests, five Huawei regression tests, the band-list regression and the hidden/visible polling callback checks. They complement the profile smoke runs rather than replace hardware validation.
