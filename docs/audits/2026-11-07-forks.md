# Fork audit, 2026-11-07

## Coverage and comparison method

GitHub reported **18 forks and network_count=18** for `fildunsky/luci-app-5gmodem`. The complete paginated fork list was checked. None advertised child forks. All **36 branch heads** in those forks were inspected, including feature branches rather than only each default branch. Tags and deleted/unreachable branches are outside this snapshot.

Published baseline: `3c21fafa6c2c0f2b7aaadac5a24faaad2fc6c00b` (3.9.23 README links). Local HEAD: `709838f212853844232de11bf9108aae5604cdcc`; their tracked differences are only six README files. Findings were also checked against the current working tree, including the uncommitted runtime audit fixes.

A separate bare repository was used; the application worktree and router were not modified. Comparisons used reachability and patch equivalence (`git log --cherry-pick --right-only --no-merges`) before manual review. This matters because several forks retain rewritten copies of our release history: commit counts alone falsely suggest dozens of new changes. Two Git fetches failed with TLS errors; GitHub API branch SHAs were obtained instead, and every referenced object already existed locally. Their heads were therefore verified without excluding either fork.

## Candidates worth considering

### 1. Preserve user network options during interface recreation

[VoidInTheShell, focused runtime-intent patch](https://github.com/VoidInTheShell/luci-app-5gmodem/commit/3962dc9c7ebacb63002e97408dcce3fc5ddad158) preserves the existing interface section and removes transport-specific keys instead of deleting the entire section. This can retain MTU, routing-table settings and DNS lists that are not all covered by our current explicit save/restore fields. It also serializes creators with flock and re-checks ownership before delayed workers start an interface.

The useful parts should be separated from the policy rewrite. The same patch removes our bounded recovery of runtime `autostart=false`, and the PortalWRT master variant changes defaults/protocol preference. Our 900-second recovery rule has a documented reason: an interrupted recovery can leave an interface stopped without a persistent user disable. Importing a permanent stopped-state prohibition would change automatic recovery. The current implementation already distinguishes persistent disables and protocol errors, and already guards old-route deletion with a check that the replacement route exists. Those parts are not missing fixes.

Priority: small option-preservation and creator-concurrency changes, each with recreation/boot/manual-stop cases; do not replace the full runtime-state machinery as one change.

### 2. RM520N-GL mode changes through the QMI interface

[stevenjoezhang c10ab44](https://github.com/stevenjoezhang/luci-app-5gmodem/commit/c10ab4434f402b2282efdb5791db9a8abee814f5) adds a narrow path for product RM520N-GL, VID:PID 2c7c:0801, a bound qmi interface and uqmi with 5gnr support. It writes `network.<iface>.modes`, persists the selected mode and asks netifd to reload, instead of changing RAT live through AT. The commit describes a data-session loss after a live AT mode change.

This path is absent from our current code. Our Quectel common2 profile is marked `_BANDS_APPLY_LIVE=1`, so a normal mode write does not force a redial. The idea deserves a QMI-specific regression/hardware test. The exact patch also calls global `ubus call network reload`, uses an exact product-name guard and couples persisted netifd modes to AT mode control. Review whether a targeted reconnect can solve the problem before adopting that scope. This is an author-reported failure, not one reproduced on our current Compal/MBIM+MM stand.

### 3. Optional GL-E750/v2 controls

[Storm-10 07e7088](https://github.com/Storm-10/luci-app-5gmodem/commit/07e7088eeb87edc9435b76d1b6cb9bfc4467c953), plus [translations](https://github.com/Storm-10/luci-app-5gmodem/commit/c1217d9e3518485af4758dd64cdf51276595de81), adds switch-on/off, a long-press button, a double-flip gesture and display/SMS settings. Backend detection checks the GL-E750 board and `/usr/bin/mcu-switch`; this hardware-specific UI is absent from our tree.

The branch does not include the display/gesture daemon implementing the new mcu_* settings and `mcu-switch sms/metrics/standby` commands. Its sms_led.sh, smscmd.sh and button hotplug handler are unchanged from upstream. Thus the new UI alone is not a complete display/gesture implementation; the matching external mcu-switch implementation and its interface contract are needed.

The added help for `CMD_OUTPUT <number>` also has no implementation in the included SMS command runner. Our existing runner already appends up to 600 bytes of command output to enabled replies; the new placeholder/character-count/multipart semantics cannot be claimed from this patch. A changed `this.value()` in LED loading is cleaner binding, but our current function leaves `o` pointing to that same final option, so this alone is not a reproduced bug.

Priority: optional, board-scoped integration once its external component is available; no extra worker on other routers.

### 4. FM350 diagnostic command catalogue

[win64exe 0253811](https://github.com/win64exe/luci-app-5gmodem/commit/02538116c96bc407c84a2ef42808fd5b9ada1be5) expands fm350.user. Our current file already contains many of its useful reads: GTCAINFO, CESQ, CSCON, COPS, CEREG, CGCONTRDP, GTDNS, GTRXPATHEN and CPIN. Remaining candidates include CGMR/CLAC/CNUM/GTCURCAR reads and an explicitly long operator scan. Some examples actively change RAT/bands or reset the modem and should not be imported as unqualified presets. In particular, GTACT modes must match our tested model/firmware mappings. This is a smaller usability improvement, not a new modem driver.

## Already present or not suitable for direct import

- [mskvortsov e83f319](https://github.com/mskvortsov/luci-app-5gmodem/commit/e83f319db69fd52437785f2cc69f30cc7edf9c39): spaces after CEREG/C5GREG/CREG commas are already supported. Offline calls to our actual `_fibocom_reg` returned 1 for `+CEREG: 2, 1, 4554, 000DB80B, 7`, and 5 for its roaming variant.
- [urbnywrt ee0f949](https://github.com/urbnywrt/luci-app-5gmodem/commit/ee0f949ee2c4b756e377f83cf52fe1fce402e73d): Nikki backend, panel card, service mapping and IPv6 controller-port parsing already exist locally. Fork-specific updater URLs/version branding should not be copied.
- [CHIENNT97 0ccd676](https://github.com/CHIENNT97/luci-app-5gmodem/commit/0ccd6769ce5150e3b55c241dd2830fdb8fc583f0): separate NR signal lines and Serving PCI fallback already exist in our Sierra profile. Its broad `*ENDC*` pattern catches `ENDC_SA` before the SA arm. Running the actual case blocks produced **ours: 5G SA; fork: 5G NSA** for ENDC_SA/n78. For ENDC with no NR band, ours reports LTE and the fork forces NSA. Do not import the mode heuristic wholesale.
- [mareksj1901 firewall card](https://github.com/mareksj1901/luci-app-5gmodem/commit/e23cc41f0c3eff9229f36d6c1e47cc65cc6ede7e): the one-click reload UI is absent and usable as an optional diagnostic action, but the patch puts it into every bar without a visibility setting. It is lower priority than the underlying connectivity fixes.
- [mareksj1901 recovery reload](https://github.com/mareksj1901/luci-app-5gmodem/commit/51b9ffe0c6da79ab7668b62c4657dcdc6b226210): unconditional firewall reload on each recovery would add work and potentially overlap jobs. Our `fw_zone_check` already reloads when the current device is missing from the live firewall rules. Keep a scoped repair.
- Japanese translation in taku42 is patch-equivalent to upstream; other unchanged/rebased forks provide no separate runtime feature.

## Historical project experiments preserved in forks

These commits are authored by our project, not new third-party implementations. They are absent from current master but remain reachable in several forks:

- [atd](https://github.com/mareksj1901/luci-app-5gmodem/commit/355cbed2dd506975321c0689f7be3ac9e0f4be5a): optional URC listener on a spare AT port. It can motivate event-driven recovery, but does not replace the current polling architecture. The source opens the device without CLOEXEC and does not close its fd before the handler exec, despite the comment promising that; this needs correction before reuse. A spare safe port and coexistence with MM/SMS also need validation.
- [dashboard](https://github.com/mareksj1901/luci-app-5gmodem/commit/9bf1f333b29d72cb36d073f73aaa06d745708666): 630-line experimental metrics page, explicitly not connected to menu/ACL in its commit. Useful as design material, not a ready enabled feature.
- [sketch/qmip](https://github.com/chacuavip10/luci-app-5gmodem/commit/a0670148e7918d4badfbf29d1d88a898c1a423d4): shelved QMI+MM protocol. Its own notes describe traffic stopping after 2–50 minutes with growing rx_errors while WDS still says connected. Our current MBIM+MM path is not justification for reviving this QMI experiment unchanged.

## Outcome

No fork code was imported and no router changes were made during this review. The first candidates are isolated preservation of user network options and a tested RM520N/QMI mode-change path. GL-E750 is a separate optional integration requiring its runtime component. The comparison metadata, branch SHAs and patches are retained in the external research checkout for follow-up.


## Integration follow-up

The first two candidates were adapted locally after the review. Interface
recreation now preserves the section and DNS list types, without the fork's
runtime-stop policy rewrite. Creator serialization and delayed-worker ownership
hardening remain separate follow-up work. RM520N-GL/QMI manual mode changes now
use the netifd modes setting with target/ownership and pending-edit guards.
A reload is required to load changed UCI options; an unchanged mode is reapplied
by cycling only its bound interface. Temporary USSD mode changes keep the AT path.
The fork author's report is accepted as hardware evidence; local regression tests
verify configuration handling and dispatch. Contact the author for an integrated
release test after publication, not before a release exists.
