# Телеметрия 5gmodem: как забирать метрики в умный дом и куда угодно ещё

Приложение раз в круг сторожа (обычно 15–30 секунд) записывает плоский JSON с
метриками активного модема в единый файл:

```
/tmp/5gmodem_tele.json
{"sig":67,"oper":"T-Mobile","rsrp":-104,"rsrq":-11,"sinr":14,"temp":34,"band":"B3","mode":"4G","ping":88,"rx":5865635,"tx":112640,"sms":0}
```

Это **единственная поддерживаемая точка** для внешних потребителей: умного дома,
внешних дисплеев, чужих дашбордов, скриптов. Забирать данные отсюда, а не
вызовами наших скриптов: файл дешёвый (пишется из уже собранного снимка метрик,
ни одного лишнего запроса к модему), а каждый внешний вызов `5gmodem.sh` — это
полный форк опроса и очередь к AT-порту.

Формат канонический: короткие имена полей, единица зашита в поле, числа числами — одинаково для всех потребителей.

## Поля

| Поле | Тип | Единица | Смысл |
|---|---|---|---|
| `sig` | 0..100 | % | Качество сигнала, сведённое к процентам |
| `oper` | строка | — | Имя оператора |
| `rsrp` | int | dBm | Мощность опорного сигнала (дробное от модема округляется к ближайшему) |
| `rsrq` | int | dB | Качество опорного сигнала |
| `sinr` | int | dB | Сигнал/шум |
| `band` | строка | — | Первичная несущая одним токеном: `B3`, `n78` |
| `ca` | строка | — | Активная агрегация: `B3+B7+n78` (PCC первым; поля нет, если несущая одна) |
| `mode` | строка | — | `2G` / `3G` / `4G` / `4G+` / `5G NSA` / `5G SA` |
| `temp` | int | °C | Температура модема |
| `ping` | int | мс | Последний замер сторожа через интерфейс модема |
| `rx`, `tx` | int | Б/с | Скорость: дельта счётчиков ядра между двумя записями файла |
| `sms` | int | шт | Непрочитанные SMS |
| `cc` | строка | — | Код страны внешнего адреса (`RU`, `NL`) — появляется, когда включён «Внешний IP» |
| `wan_ip`, `ext_ip`, `ext_ip6` | строка | — | Адреса — только при `tele.publish_ip=1` (по умолчанию их здесь нет, см. ниже) |

Правила (из схемы, здесь они соблюдаются строго):

* **Нет данных — нет ключа.** Ни `0`, ни `-1`, ни прочерков. Ноль значит
  настоящий ноль (например, `sms:0` — непрочитанных нет).
* **Свежесть.** Если снимок метрик протух (модем вынут, интерфейс лежит) —
  модемные поля исчезают из файла целиком, остаются только живые (`sms`).
  Потребитель отличает «модем без данных» от «экспортёр умер» по mtime файла:
  файл продолжает переписываться, пока работает сторож.
* **Приватность by design.** В файле никогда нет IMEI, IMSI, ICCID, номера
  телефона и идентификаторов соты. Адресов по умолчанию тоже нет — ни
  выданного оператором, ни внешнего; из внешнего сюда попадает только код
  страны (`cc`): он никого не идентифицирует, а отвечает на тот самый вопрос,
  ради которого внешний адрес и смотрят — через какую страну роутер выходит
  наружу. В таком виде файл можно отдать наружу, не подумав дважды. Адреса
  добавляются одной настройкой (`tele.publish_ip=1`) — осознанно и на своих
  условиях.
* **Атомарность.** Файл переписывается через временный + `mv` — читатель
  никогда не увидит половину JSON.
* Скорость `rx`/`tx` усредняется по окну между двумя записями (интервал тика
  сторожа). Первая запись после старта поля не содержит — прошлой точки нет.
* **Осечки опроса не публикуются.** Если очередной сбор вернулся без
  сигнального ядра (порт был занят), а прежний файл ядро содержал — файлы не
  переписываются. «Свежий файл без модемных полей» появляется только когда
  модем реально недоступен дольше TTL — на этот контракт можно полагаться
  строго.

Сейчас в файл попадает **активный модем**. Для мультимодемных конфигураций
формат зарезервирован (`/tmp/5gmodem_tele_<usb-путь>.json`), но пока не пишется.

## Файл-приложение: детали соты (только локально)

Рядом пишется второй файл — `/tmp/5gmodem_tele_cell.json` — с деталями
обслуживающей соты для локальных экранов и страниц:

```
/tmp/5gmodem_tele_cell.json
{"pci":1,"earfcn":1000,"enb":100001,"cid":10000001,"tac":10001,"apn":"internet","wan_ip":"203.0.113.10","modem":"Quectel EC21"}
```

Значения в примере выдуманы намеренно: `wan_ip` — из диапазона 203.0.113.0/24,
который RFC 5737 отводит под документацию, идентификаторы соты — круглые числа.
В примерах к этому файлу нельзя показывать снимок с живого устройства: по
`cid`/`tac`/`enb` определяется примерное положение, а `wan_ip` маршрутизируем.

| Поле | Тип | Смысл |
|---|---|---|
| `pci` | int | Physical Cell ID |
| `earfcn` | int | Номер частотного канала |
| `enb` | int | Идентификатор базовой станции (eNB/gNB) |
| `cid` | int | Идентификатор соты |
| `tac` | int | Код зоны отслеживания |
| `apn` | строка | Активная точка доступа |
| `wan_ip` | строка | Адрес, выданный оператором |
| `ext_ip`, `ext_ip6` | строка | Внешний адрес — каким роутер виден интернету ЧЕРЕЗ ЭТОТ МОДЕМ. Есть, когда включён «Внешний IP» |
| `modem` | строка | Модель модема |
| `nbrs` | массив | Соседние соты: `[{"band":"B7","pci":94,"rsrp":-104,"rsrq":-12,...}]` |
| `mcc` | int | Serving MCC |
| `mnc` | строка | Serving MNC — строкой: ведущий ноль значащий (250-02 ≠ 250-2) |
| `lac` | int | Location Area Code |
| `cid_hex` | строка | Идентификатор соты в hex |
| `bandwidth`, `txpower`, `uecat`, `volte`, `mimo`, `rxdiv`, `antports`, `therm`, `fw` | строка | Витринные значения как в снимке метрик |
| `pathloss`, `cqi`, `csq`, `rssi`, `conn_time`, `simslot`, `roaming`, `nca` | int | Числовые детали (conn_time — секунды, nca — активных вторичных несущих) |
| `s1band`..`s4state` | — | Несущие агрегации: band/pci/earfcn/rsrp/rsrq/sinr/state на слот |
| `phone` | строка | Номер SIM — только здесь, в локальном файле; в публикуемый не попадает никогда |

Он подчиняется тем же правилам (атомарность, свежесть, «нет данных — нет
ключа»), но **наружу не публикуется никогда**: идентификаторы соты локализуют
положение устройства, а `wan_ip` — маршрутизируемый адрес. В MQTT-состоянии,
HTTP-симлинке и любых внешних потоках участвует только основной файл — потому
обещание приватности выше относится именно к нему и остаётся в силе.

## Внешний адрес

`ext_ip` в файле-приложении — это адрес, каким роутер виден интернету **через
этот модем**, а не по маршруту по умолчанию: у файла про модем и адрес должен
быть модема, иначе рядом с `wan_ip` оказался бы адрес соседнего аплинка.
Сравнение этих двух полей и есть ответ на вопрос «сидим за CGNAT/туннелем или
нет»: разные — да, одинаковые — оператор выдал белый IP.

Поля появляются, только когда в настройках включён «Внешний IP» (по умолчанию
выключен: это запрос к постороннему сервису). Спрашивается он не чаще, чем
задано интервалом обновления — телеметрия берёт готовый кэш, своих запросов не
делает.

В публикуемый файл из этого по умолчанию попадает только `cc` — код страны.
Сами адреса маршрутизируемы, поэтому живут там же, где `wan_ip`: в локальном
файле.

### Если адреса всё-таки нужны в MQTT

```sh
uci set 5gmodem.tele.publish_ip=1
uci commit 5gmodem
```

Тогда `wan_ip`, `ext_ip` и `ext_ip6` появятся и в публикуемом файле, а
`telemetry.sh discovery` заведёт под них сенсоры в Home Assistant.

Что при этом стоит знать. Основной файл уезжает в MQTT и, если вы включили
рецепт из «Способа 4», раздаётся по HTTP всем в LAN без авторизации. Домашние
брокеры часто живут без пароля или с одним логином на все железки, а Home
Assistant пишет состояния сенсоров в историю и уносит её в бэкапы. Один адрес
сам по себе не тайна — его видит каждый открытый сайт; но поток адресов со
штампами времени это уже журнал: когда адрес менялся, когда лежал туннель,
когда роутер был включён. В замкнутом домашнем контуре это никого не касается,
и настройка ровно для такого случая — но включить её должен человек, а не мы за
него.

## Агрегация: активная и спящая несущая

Ловушка, на которой спотыкается почти каждый потребитель. Слоты `s1..s4` в
файле-приложении описывают **всю сконфигурированную** агрегацию, включая
спящие несущие, - судить по факту «слот есть» об активной агрегации нельзя.

Сеть заранее собирает вторичные несущие и держит их выключенными, пока нет
трафика. Различает их единственное поле - `state`:

* `"deactivated"` - резерв: несущая сконфигурирована, но данных не несёт;
* `"activated"` - работает прямо сейчас.

Под нагрузкой состояние меняется за секунды в обе стороны. Уровни у спящей
несущей ЕСТЬ (она измеряется), поэтому наличие RSRP или SINR тоже не признак
активности.

Что брать для показа - готовое, вычислять ничего не надо:

| Хотите показать | Берите |
|---|---|
| ярлык «агрегация есть/нет» | `ca` в основном файле: строка только из активных несущих, ключа нет - активной агрегации нет |
| число активных вторичных | `nca` в файле-приложении (спящие не считаются; `nca:0` при заполненных `s1..s4` - норма) |
| детальную таблицу несущих | `s1..s4`, спящие показывать резервом (приглушённо), а не работающими |

## Включение и настройки

Работает из коробки, настроек не требует. Все опции — в uci-секции `tele`
(секции может не быть — это нормально, умолчания зашиты):

```sh
uci set 5gmodem.tele=tele
uci set 5gmodem.tele.enabled=0        # выключить экспорт совсем (по умолчанию включён)
uci set 5gmodem.tele.name=mybox       # имя устройства для MQTT (по умолчанию hostname)
uci set 5gmodem.tele.publish_ip=1     # класть адреса и в публикуемый файл (по умолчанию нет)
uci commit 5gmodem
```

## Правила для потребителя

Пять правил, общих для любого способа ниже. Они не пожелания: файл устроен так,
что при их соблюдении потребитель показывает правду, а при нарушении - врёт.

1. **Нет ключа - нет данных.** Не подставляйте `0`, `-1` или прочерк вместо
   отсутствующего поля: на экране - прочерк, в бинарном протоколе поле не
   передавать, в MQTT ключа нет. Ноль в файле означает настоящий ноль.

2. **Свежесть - по mtime файла, а не по содержимому.** Порог: **90 секунд**.
   Файл старше - экспортёр не работает (пакет удалён, сторож остановлен), и
   вся модемная карточка у вас недоступна. Файл свежий, но модемных полей нет -
   это штатное состояние «модем вынут или интерфейс лежит»: показывайте именно
   это, а не последние удачные значения.

3. **Не кэшировать поверх.** Прочитал - показал. Своих «липких» последних
   значений не хранить: честность файла - наша забота, и подмена его памятью
   потребителя ломает пункт 2.

4. **Читать не чаще раза в секунду.** Файл всё равно переписывается раз в круг
   сторожа (15-30 секунд). Более частое чтение не даст новых данных, только
   нагрузит роутер.

5. **Публикатор MQTT должен быть один.** Если на роутере уже есть свой
   агрегатор, публикующий состояние в тот же брокер, - не включайте наш
   (не задавайте `5gmodem.tele.mqtt_host`), а заберите наш JSON файлом и
   отправьте вместе со своими полями. Иначе в Home Assistant появятся два
   устройства с пересекающимися сенсорами.

### Если у вас свои метрики рядом с нашими

Мы пишем **только модемные поля** и только в свой файл. Системные метрики
(батарея, процессор, память, VPN, Wi-Fi) - забота вашего агрегатора, и писать
их надо в свой файл, а не дописывать в наш: наш переписывается целиком каждый
круг, чужие ключи в нём не переживут ни одной записи.

Потребитель (экран, шлюз в умный дом, MQTT) **сливает оба файла** при отправке.
При совпадении имён ключей модемные значения берутся из нашего файла.

| Кто | Пишет | Куда |
|---|---|---|
| 5gmodem | `sig oper rsrp rsrq sinr band ca mode temp ping rx tx sms cc` (+ адреса при `publish_ip=1`) | `/tmp/5gmodem_tele.json` |
| Ваш агрегатор | всё остальное | свой файл |

## Чего читать не надо

Рядом в `/tmp` лежит внутренний снимок метрик — `/tmp/5gmodem_metrics_<путь>.json`.
Его находят и начинают разбирать, а потом удивляются, что «путь другой и поля
называются иначе». Так и есть: это не интерфейс, а рабочий файл приложения.

* **Имя зависит от USB-пути модема** (`/tmp/5gmodem_metrics_2_1_4.json`,
  `..._1_2.json`) и меняется, стоит переставить модем в другой порт.
* **Поля внутренние и длинные** — `signal`, `operator_name`, `mtemp`, `enbid`,
  `cid_dec`, `conn_time_sec`. Мы переименовываем их, когда это удобно коду.
* **Значения свёрстаны для интерфейса**, а не для машин: `"mtemp":"36 &deg;C"`
  (да, с HTML-сущностью), `"rx":"7.2 KiB"`, `conn_time` строкой «0d, 00:22:35».
* Никакого обещания совместимости у него нет и не будет.

Всё, что нужно потребителю, есть в `/tmp/5gmodem_tele.json` каноническими
именами и числами: `sig`, `oper`, `rsrp`, `rsrq`, `sinr`, `band`, `ca`, `mode`,
`temp`, `ping`, `rx`, `tx`, `sms`. Детали соты — в `/tmp/5gmodem_tele_cell.json`.

## Способ 1: локальный файл (дисплеи, скрипты на самом роутере)

Просто читайте `/tmp/5gmodem_tele.json`. Разбор — `jsonfilter`:

```sh
jsonfilter -i /tmp/5gmodem_tele.json -e '@.sig'      # 67
jsonfilter -i /tmp/5gmodem_tele.json -e '@.mode'     # 4G
```

Файл может не содержать поля (см. «нет данных — нет ключа») — проверяйте
пустой ответ.

## Способ 2: по SSH (чужой дашборд, самописный опрос с другой машины)

```sh
ssh root@192.168.1.1 cat /tmp/5gmodem_tele.json
```

Одна команда — один дешёвый `cat`. Никаких вызовов rpcd и наших скриптов.

## Способ 3: MQTT + Home Assistant

Нужен `mosquitto_pub` на роутере (`apk add mosquitto-client-nossl` или
`-ssl`) и брокер. Настройка:

```sh
uci set 5gmodem.tele=tele
uci set 5gmodem.tele.mqtt_host=192.168.1.50
uci set 5gmodem.tele.mqtt_port=1883          # необязательно
uci set 5gmodem.tele.mqtt_user=ha            # необязательно
uci set 5gmodem.tele.mqtt_pass=secret        # необязательно
uci set 5gmodem.tele.mqtt_topic=5gmodem/dacha  # необязательно, по умолчанию 5gmodem/<hostname>
uci commit 5gmodem
```

С настроенным брокером сторож сам публикует состояние каждый круг:

```
5gmodem/<имя>/state      {"sig":67,"oper":"T-Mobile",...}
5gmodem/<имя>/available  online
```

Автообнаружение Home Assistant — один раз после настройки брокера:

```sh
/usr/share/5gmodem/telemetry.sh discovery
```

Появится устройство со всеми сенсорами (сигнал, RSRP/RSRQ/SINR, температура,
оператор, режим, агрегация, пинг, скорости, SMS, страна выхода). Темы discovery публикуются с
retain — переживают перезапуск HA.

## Способ 4: HTTP (внешний дисплей без SSH)

Из коробки файл наружу по HTTP **не** отдаётся — сознательно. Если очень нужно
(дисплей в LAN умеет только HTTP GET), отдайте его uhttpd-ом вручную:

```sh
ln -s /tmp/5gmodem_tele.json /www/tele.json
```

и заберите `http://192.168.1.1/tele.json`. Помните: файл станет виден всем в
LAN без авторизации. Идентификаторов в нём нет, но имя оператора и уровень
сигнала — тоже информация; решение за вами. Симлинк не переживает перезагрузку
роутера — добавьте команду в Автозагрузку (rc.local), если нужен постоянный.

## Отладка

```sh
/usr/share/5gmodem/telemetry.sh show    # текущий файл
/usr/share/5gmodem/telemetry.sh write   # собрать прямо сейчас
/usr/share/5gmodem/telemetry.sh publish # собрать и отправить в MQTT
logread | grep 5gmodem                  # если что-то не так
```

Пустые модемные поля при работающем модеме — обычно значит, что страница
«Сеть» давно не открывалась и снимок метрик не обновлялся: сторож обновляет
его сам в фоне, подождите один круг (до минуты) или откройте страницу.
